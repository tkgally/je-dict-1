# Entry Design

**Last updated**: 2026-04-05

## Schema overview

Every entry is a JSON file validated against `build/schema.json`. The key top-level fields:

```
id              — "XXXXX_romaji" format (permanent, used in URLs)
headword        — Japanese writing with furigana: {漢字|かんじ}
reading         — Full hiragana reading
romaji          — Romanized reading
senses          — Array of sense objects (definitions)
examples        — Array of example sentence objects
notes           — Structured text field (English prose with Japanese examples)
metadata        — Tags, timestamps, schema version, vocabulary tier
conjugation     — (verbs/i-adjectives only) Full conjugation table
cross_references — Links to related entries
prominent_see_also — High-priority related entries shown prominently
```

## Senses

Each sense has:
- `sense_number` — Sequential integer
- `definition` — English gloss
- `tags` — Semantic labels for this sense

Multi-sense entries are common, especially for verbs with literal and figurative uses.

## Examples

Requirements per the v2 quality standards:
- **Minimum 3 examples per sense** (not per entry)
- **Progressive length** — short → medium → longer within each sense
- **sense_numbers field** — every example must specify which sense(s) it illustrates
- **Furigana on all kanji**
- **No inline word links** during creation (added in polishing)

Example ID format: `{entry_id}_ex{N}` (e.g., `01234_taberu_ex3`)

## Notes field

The notes field is a critical quality differentiator. Requirements:
- **Section headers** — labeled headers (USAGE:, COLLOCATIONS:, SIMILAR WORDS:, etc.)
- **Bullet points** — lists of 2+ items use `- ` bullets, not comma-separated inline
- **Paragraph breaks** — `\n\n` between sections
- **All prose in English** — Japanese appears only in example phrases/collocations
- **Furigana on all kanji**

Minimum content: core semantic explanation + collocations + one additional section.

## Metadata

```json
"metadata": {
  "tags": {
    "pos": ["verb-godan"],        // Part of speech (strict enum)
    "semantic": ["movement"]       // Semantic categories
  },
  "vocabulary_tier": "general",    // All new entries: "general"
  "schema_version": "2.0",
  "date_created": "2026-04-05T...",
  "date_updated": "2026-04-05T..."
}
```

POS tags use hyphenated names: `verb-suru`, `verb-godan`, `adjective-na`, `adjective-no`, etc.

## Conjugation tables

Verbs and i-adjectives include a `conjugation` field with all forms hard-coded in JSON. Generated by `add_conjugations.py` (verbs) and `add_adjective_conjugations.py` (i-adjectives). Forms cover dictionary, masu, te, ta, nai, potential, passive, causative, imperative, conditional, volitional, and more.

## Cross-references

Two types:
- **`cross_references`** — standard related-entry links, shown in a "See also" section
- **`prominent_see_also`** — high-priority links shown prominently (e.g., transitivity pairs, antonyms)

Each reference includes `entry_id`, `headword`, `reading`, `relationship` (e.g., "synonym", "antonym", "transitive pair").

## Furigana

All kanji must have furigana in all fields: `{漢字|かんじ}`. This is enforced by `find_missing_furigana.py` and is a critical quality requirement for the target audience (intermediate learners still building kanji knowledge).
