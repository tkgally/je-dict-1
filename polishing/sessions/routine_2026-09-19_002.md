## What happened

Ran `build/review_accuracy.py --range 3001 4000 --budget 2.5`: 1,000 entries
reviewed, 144 flagged (14.4%, within the noise threshold), est. cost $0.48.

Adjudicated every surviving issue (149 individual issues across 144 flagged
entries) by family, opening each entry and, for notes-fact and register
flags, checking the note text and my own linguistic knowledge before acting:

- **offvocab** (13 issues, 11 entries): all applied — migrated off-list
  semantic tags to the closest in-list tag (e.g. `social`→`society`,
  `equipment`→`tool`, `place`→`military`).
- **wrong-category** (37 issues, 35 entries): all applied — removed
  semantic tags that didn't fit the headword (e.g. `body-part` on 痛む,
  `furniture` on 出身, `color` on 城), replacing with a fitting tag or
  leaving the entry untagged to match sibling prefix entries.
- **register** (34 issues): 13 applied, 21 rejected. Most flags claimed a
  `formal` tag contradicted a hedge in the note ("slightly formal"); I kept
  `formal` where the note still leaned formal (no "semi-formal" tag exists)
  and only changed the tag where the note explicitly called the word
  neutral or casual (e.g. 独身, 老人, じゃ, 文句) or where the note's own
  table contradicted the tag (どうぞよろしく).
- **gloss-meaning / translation-meaning** (23 issues): 14 applied, 8
  rejected. Applied fixes added a missing sense to a truncated top-level
  gloss (役立つ, どうぞよろしく, ドラマ), corrected mistranslated examples
  (宝の持ち腐れ was rendered as "pearls before swine", a different English
  idiom; 株式会社→株 rendered as "corporation"→"stock" in English, which is
  nonsensical), and fixed a wrong nuance (address→recipient's name for
  宛名). Rejected flags where the entry's own sense-level structure already
  covered the nuance the reviewer wanted (割, 密, 万一).
- **notes-fact** (66 issues, 56 entries): 27 applied, 29 rejected. This
  family had a real false-positive rate — several flags described the note
  as if it had an error the note doesn't actually contain (the reviewer
  model appears not to always parse the furigana `{kanji|reading}` markup,
  so it occasionally treats two different readings of the same kanji as
  unexplained duplicates). Genuine fixes applied: a kanji error (拍手 was
  given the reading かしわで in two places; the shrine-clapping word is
  written 柏手, not 拍手), two fabricated alternate readings for 翌朝/翌月,
  an inconsistent 町/村 reading in a hierarchy diagram, a wrong okurigana in
  an accounting term (借り方→借方), a self-contradictory grammar note
  (とんでもない), a duplicated related-word line, a mis-shelved example
  (豆まき under the "miniature" sense of 豆〜, まるで違う under "total
  negation"), a politeness tag (honorific→humble for the self-deprecating
  ご無沙汰), and one transitivity tag (迫る intransitive→both, since 返事を
  迫る is genuinely transitive). Rejected flags mostly restated content the
  note already got right (verified against the furigana), or nitpicked a
  hedge ("slightly formal", "archaic") that's still defensible.

Every decision is logged in `reviews/decisions.jsonl` with a `note` giving
the reasoning in ≤10 words.
