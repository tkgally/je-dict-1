## Work

### 1. Built the detector the item had been asking for

`build/check_stale_noentry.py` — read-only, never modifies entries, in the same shape as the
other systemic-fix detectors (`--summary`, `--json`, `--class`, `--mechanical`, `--range`,
`--limit`). It scans every `⟦surface→base：noentry⟧` marker, looks `base` up in
`build/word_id_lookup.json`, and stratifies:

| Class | Meaning | Fix mode |
|---|---|---|
| A1 / A2 | headword match, multi-char, exactly one candidate (A2 = katakana) | mechanical |
| A3 | headword match, several candidates | per-entry |
| B / C / D | single-char headword, reading-only, reading-only single-char | per-entry / reject |
| **R** (new) | would be A1/A2, but the surface's own furigana contradicts the target's reading | per-entry |

Each record also carries `wrong_when_written` (target created before the entry the marker sits
in), per the 2026-08-02 provenance analysis.

Baseline at start: 7,346 marker instances / 6,526 distinct pairs in 3,131 entries; 2,619 pairs
looked mechanical before the reading test, 2,579 after.

### 3. Disproved this item's central claim, and encoded the fix

P35 predicted precision "near 1.0" for the whole A1+A2 batch. That holds for long compounds and
**fails for 2–3 character bases**, where hand review found ~4% false positives:

- polysemous loanword in another sense — baseball ⟦フライ⟧ → `11124_furai` *deep-fried food*
- abbreviation inside a compound — ⟦パン⟧ in 海パン → `00553_pan` *bread*
- homograph read differently — ⟦{臭|にお}い⟧ → `01133_kusai` (くさい)
- bound, rendaku'd compound element — ⟦{張|ば}る⟧ in 形式張る → `12583_haru` (はる)

The last two are now caught mechanically by class R (reading comparison with prefix, honorific
and suru-verb tolerances). The first two are invisible to any string test, so the remaining
1,580 pairs — all 2–3 character bases — were re-filed as `fix_type: verify`, `verify: per-entry`
in `backlog-queue.json`, and P35 in `cleanup-backlog.md` got a dated update section recording the
measurement.

### 4. Self-check (§4) — clean

Link-target substitution is not what `review_runner.py`/`review_accuracy.py` judge, so the
independent check was a targeted one: a stratified 60-pair sample of the applied fixes (30 short
base, 30 long) sent to `google/gemini-2.5-flash` with context, asking whether each new target is
the right word. **0 flagged.** As a control, the same checker was run over 6 known-bad class-R
cases and flagged 2 of them (including the 形式張る bound-morpheme case), so the clean result is
informative rather than agreeable. No `reviews/decisions.jsonl` lines — nothing was reported to
adjudicate. Est. cost $0.0025, logged to the ledger with `phase: "self-check"`.
