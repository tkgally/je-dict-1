## Code change (build/auto_link.py)
- `guard()` returned early for any surface that is not pure hiragana, so an `unlink` decision for a kanji or katakana surface was ignored and `review_links.py --apply-decisions` put the link straight back. It now honours decisions for every surface; the homophone block tier still applies to kana surfaces only.
- The function-word rule (particles, table verbs) and the verb-chain rule returned their candidate without calling `guard()`; both now go through it.
- The verb-chain rule dropped the entry's own id from the candidates and then linked to whatever was left, so 直して in 直す linked to the suffix entry 〜直す. A form of the entry's own headword is now always treated as self, as `_resolve_span` already did for single tokens.
- Tests: three new tests in build/tests/test_auto_link.py (decision holds for kanji/katakana; for function words and chains; own headword forms never link to a same-spelled entry). All three fail on the old code and pass on the new.
- Function words in the block tier: none today, so routing them through `guard()` changes no existing behaviour.
