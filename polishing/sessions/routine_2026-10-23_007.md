# Routine 2026-10-23 cycle 7 — systemic-fix

- Mode: systemic-fix (selector: "highest scheduler debt among eligible modes"); backlog item `auto-link-kanji-surface-ledger`, narrowed in cycle 4 to its last part: a one-occurrence `retarget` acted as an entry-wide unlink.

## Cause
- A retarget line counted as `unlink` for the old (entry, base, target) in two places: `auto_link.load_unlink_decisions()` (so the linker excluded the base in the whole entry) and `check_link_homophones.decision_index()`.
- `review_links.py --apply-decisions` uses that index to strip "stray" links whose key has an unlink and no keep, so retargeting one です (base だ) in 01799 stripped every だった link to だ in the entry. The CI gate also demanded a `keep` for them. That is why 01799 needed a restoring keep line on 2026-10-08.

## Change
- `load_unlink_decisions()` counts only `unlink` lines; `decision_index()` records a retarget as `retarget` for the old key (still `keep` for the new one). The retier statistics still count a retarget as evidence the old link was wrong.
- Tests: `test_retarget_leaves_other_links_to_the_old_base` (new; fails on the old code) and two existing tests updated to the new semantics.
- inline-word-links skill: the ledger paragraph now says an unlink holds on every surface and a retarget pins one occurrence.

## Effect on data
- 127 retarget lines in 110 entries. Running the linker on those entries with the old and the new code differs by one link: 19539 でございます, "でいらっしゃる — honorific copula", where いらっしゃる now links to いらっしゃる (correct). Not applied in this cycle; the next mechanical pass over 19539 adds it.
