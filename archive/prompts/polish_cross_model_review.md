Process multi-model review reports and apply corrections where appropriate. This is a **semantic task** — Claude evaluates each suggestion from external models and applies or rejects with reasoning.

## Task Focus

Read review reports generated by `build/review_runner.py`. For each flagged entry:
1. Read the review report
2. Read the actual entry
3. For each flagged issue:
   - Evaluate the suggestion using your knowledge of Japanese
   - If you AGREE the issue is real: fix it
   - If you DISAGREE: note your reasoning in the review log
   - If UNCERTAIN: flag for curator review

## Starting Point

```bash
cat polishing/tasks/cross-model-review/progress.txt
```

Process review files in `reviews/` that have flagged issues.

## Workflow

1. **Read the progress file** to find the next review to process
2. **List review files** in `reviews/` directory, starting from the progress entry ID
3. **For each review file** (in ID order):
   a. Load the review report from `reviews/{entry_id}.json`
   b. Check if it has any flagged issues (`summary.flagged > 0`)
   c. If no flags, skip to next
   d. Load the actual entry from `entries/{range}/{entry_id}_{romaji}.json`
   e. **For each flagged issue**:
      - Read the concern and suggested correction
      - Evaluate against the actual entry context
      - Decision: APPLY, REJECT, or FLAG
      - If APPLY: fix the entry, update modified timestamp
      - If REJECT: log reasoning
      - If FLAG: add to `reviews/needs_curator.txt`
4. **After processing each review**: Update the review file with resolution status
5. **Batch commits every ~25 entries**
6. **Update progress file** with the next unprocessed entry ID
7. **Session logging** to `polishing/sessions/cross_model_review_{date}_{nnn}.md`

## Decision Guidelines

### When to APPLY
- Both models agree on the issue (severity: "error")
- The concern clearly identifies a genuine reading error
- You independently verify the reading is wrong

### When to REJECT
- Only one model flagged it at low confidence (severity: "warning")
- The concern misunderstands the furigana format (e.g., flagging okurigana splits)
- The concern references the wrong kanji-reading pair (index confusion bug)
- The reading is a legitimate variant or context-dependent choice

### When to FLAG
- You're genuinely uncertain about the correct reading
- The issue involves a rare word or specialized reading
- Both models agree but the fix isn't obvious

## Important Notes

- Models disagree sometimes. When GPT-4.1 and Gemini disagree, use your own judgment.
- When all models agree on an issue, it's very likely real — apply the fix.
- When only one model flags something at low confidence, it's often a false positive.
- NEVER apply a correction you aren't confident about. When in doubt, flag for curator.
- Update the modified timestamp on any entry you change.
- Do NOT add inline word links (⟦...⟧) in this task.
- Check the calibration report at `reviews/calibration_report.md` for known false-positive patterns.

## Review File Update Format

After processing a review, add a `resolution` field to each issue in the report:
```json
{
  "field": "examples[2].japanese",
  "kanji": "美",
  "reading": "お",
  "model": "openai/gpt-4.1",
  "correct": false,
  "concern": "...",
  "severity": "error",
  "resolution": {
    "decision": "apply",
    "action": "Changed {美|お}いしさ to おいしさ (all hiragana)",
    "resolved_by": "claude",
    "resolved_at": "2026-04-09T..."
  }
}
```

Resolution decision values: `"apply"`, `"reject"`, `"flag"`

## Session End

When finishing:
1. Update progress file with the next entry ID to process
2. Write session log to `polishing/sessions/cross_model_review_{date}_{nnn}.md` with:
   - Date and entry range processed
   - Reviews processed (count)
   - Corrections applied (with details)
   - Suggestions rejected (with reasoning)
   - Items flagged for curator
3. Run `make build`
4. Commit and push
